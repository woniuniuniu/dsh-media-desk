# Grok Bot 与 X 工作台搭建说明

用一个独立的 GitHub 私有仓库交换文件：Grok Bot 读取 X、准备回复并通知你；插件读文件、整理候选稿；所有内容都由你亲自打开预填链接并在 X 发送。插件不会自己读取 X，也不会代发、点赞、回复、转发或关注。

**当前有一个明确阻塞：后台同步已实现，但当前设置界面还没有同步开关、“现在同步一次”按钮和连接状态行。第 4 步只能先完成账号名设置，不能把整套流程当作已经可照着界面走通。** 本说明按现有代码记录这个缺口，不要求你手改配置文件。

## 1. 在 GitHub 新建私有仓库

打开 `https://github.com/new`，填写一个仓库名（例如 x-desk-exchange），选择 **Private**，勾选添加 README，然后创建仓库。README 是仓库的说明文件，勾选后才会有初始提交和默认分支。

成功时，仓库标题附近显示 Private，文件列表有 README.md，分支为 main。以下命令按 main 编写；如果默认分支不是 main，先请维护者核对，别直接照抄。打开仓库的 Code 菜单，复制你有访问权限的仓库地址，后面用它替换 `<仓库地址>`；不要把口令或访问凭证放进地址、聊天或文件。

## 2. 把交换文件夹接到这个仓库

“工作副本”就是电脑上与远端仓库对应的本地文件夹。先打开 X 工作台设置，查看“交换文件夹位置”下的“当前使用”；默认是 `~/.dsh/x-desk/exchange/`，其中 `~` 表示你的用户目录。后台启动后会创建所需的六个子文件夹。

**交换文件夹不能放在插件代码文件夹里面。** 代码会明确拒绝：“交换文件夹在代码仓库里面，不能同步”。它也必须是一个独立仓库的根目录，不能只是别的仓库的子目录。原版插件数据目录也不能用。

打开电脑的终端，一次复制下面一个命令块，替换尖括号及其中的文字后回车；路径保留引号。这里只操作交换文件夹，绝不要在插件源码文件夹执行。任何一步报错就停下，将报错交给维护者，不用删除、重置或强制覆盖来继续。

先进入设置显示的交换文件夹，成功时终端没有“目录不存在”的报错：

```bash
cd "<你的交换文件夹>"
```

检查这个文件夹是否已有仓库，成功时输出仓库根目录；出现“不是 git 仓库”的错误才说明可以做下一条初始化：

```bash
git rev-parse --show-toplevel
```

**仅在尚未成为仓库时**，初始化名为 main 的本地分支，成功时会提示已初始化仓库；如果上一条输出的是其他父目录，先停下，不在里面继续建嵌套仓库：

```bash
git init -b main
```

将 origin（远端的本地简称）指向你刚建的私有仓库，成功时通常没有输出：

```bash
git remote add origin <仓库地址>
```

如果提示 origin 已存在，不重复添加、更不要改掉已有地址；请维护者确认它就是本次私有交换仓库后，才继续。这个仓库应仅用于交换文件，不能夹带其他项目或已经暂存的无关文件。

取回远端分支信息和初始 README 提交，成功时能看到 origin/main：

```bash
git fetch origin
```

把远端的初始提交接到本地 main，成功时交换文件夹出现 README.md；这一步让刚初始化、还没有提交的 main 真正存在，避免直接设置上游失败：

```bash
git merge --ff-only origin/main
```

这条命令也适用于能直接向前更新的已有 main 分支；如果本地已有不同历史、同名 README 或其他文件冲突，命令可能拒绝，此时停下交给维护者，保留现有文件。

让 main 记住以后与 origin/main 对应，成功时提示分支 main 已跟踪 origin/main：

```bash
git branch --set-upstream-to=origin/main main
```

这里没有要求你提交或推送任何源码。GitHub 的登录访问需要在本机事先可用；插件同步时不会弹出终端密码提示。若本机缺少 Git 或访问认证，请维护者处理后再继续。

## 3. 在 Grok Bot 连接这一个 GitHub 仓库

在你所用 Grok Bot 的连接或集成入口选择 GitHub，进入授权页后只勾选上面这个私有仓库，允许它读取仓库并新增任务输出文件；不要授权全部仓库。成功标准是 Bot 能确认该仓库并读取其中的 README.md。

仓库里没有 Grok Bot 的界面或连接器实现，本项目不能核实其菜单名称及账号支持情况。如果你找不到 GitHub 连接入口、不能将授权限定到这一个仓库，或 Bot 无法提交推送，先停止，由维护者核实当前产品能力；不要把口令粘进指令当替代办法。

## 4. 填账号名；同步界面目前待补

在工作台打开“设置”，找到“我的账号名”，填入自己的 X 账号名（不带 @，只含英文字母、数字、下划线，最多 15 个字符），点击保存。再次打开设置能看到所填账号名，才算这部分成功。把同一个账号名明确告诉 Bot 的第 04 个任务；插件不会把此设置导出到仓库。

同步默认关闭，后台默认间隔为 120 秒。开启同步意味着授权插件对这个独立交换仓库提交并推送，并从已配置的远端取回内容；它不代表授权发送 X 帖子。同步会暂存六个交换子目录里的变动、提交、取回远端、合并后再推送；它还可能提交仓库里本就已暂存的改动，因此这里应当只有交换用途的数据。

搭建 brief 所要求的操作是：打开“同步”，保存，再按“现在同步一次”，以状态行显示“已连接”作为界面验收。**当前 `client/settings.jsx` 尚未提供这些控件或状态行，这段不能当作现有可点击步骤；请在这里停下，交由维护者补齐界面后验收。** 当前仅后台有同步状态和执行接口；状态检查通过只表示仓库结构、远端和上游可用，不证明 GitHub 认证或真实推送已成功。后续仍需实际同步及文件往返验证。

## 5. 创建四个定时任务

同步入口补齐并验证后，在 Grok Bot 的定时任务入口分别新建四个任务，名称与上表对应。逐一打开上表链接，复制“复制下面整段”下整个代码块的内容到任务指令栏，包括其中的 JSON 示例；按表设置频率，保存。

每个任务都要指定第 1 步的同一个私有交换仓库。第 02 个任务另确认你的白天时段和按哪一个时区计算“每天”；第 04 个任务另说明自己的账号名；第 02、03 个任务需要能读取既有通知和答复记录，否则应先追问，不能假装没有历史。

成功时可看到四个已保存任务、各自的运行频率及完整指令。Bot 的可用调度间隔和对话记录能力由你使用的产品决定，本仓库不保证它提供这些入口；缺少能力就停下请维护者核实。保存任务不等于跑通过，真实读写留到下一步验收。

## 6. 按联调清单验证

联调清单将另外写在 `docs/spikes/`，本任务没有创建该清单；请维护者提供后逐项验证。成功标准应包含：Bot 新文件到达插件、候选稿送达对话、明确答复返回插件、本人实际发出内容被采集并进入复盘。只有文件往返和处理结果都确认，才算整条流程接通；创建仓库、保存任务或状态检查通过都不能替代这个验收。

## 出了问题怎么办

以下为 `src/sync.js` 的实际原因原文；带冒号的条目是固定前缀，后面会跟 Git 的具体报错。当前界面尚未接入这些状态，维护者可从后台同步结果判断；不要把它们理解为已经存在的界面文案。

- 「交换文件夹还不存在」：检查设置显示的路径，先启动工作台后台让它创建交换文件夹。
- 「交换文件夹在代码仓库里面，不能同步」：在代码仓库外选择独立交换位置，保留原有数据并请维护者协助转移。
- 「没有安装 git」：请维护者安装并确认插件运行环境能找到 Git，再重试。
- 「交换文件夹还不是一个 git 仓库」：按第 2 步初始化并接上新建的私有仓库。
- 「交换文件夹不是一个独立的 git 仓库」：核对仓库根目录就是交换文件夹，不能使用父仓库里的子目录。
- 「这个仓库没有配置远端」：按第 2 步核对 origin 指向你自己的私有交换仓库。
- 「当前分支没有上游分支」：先确认本地 main 已接上远端初始提交，再设置 origin/main 为上游。
- 「上一轮同步还没结束」：等待上一轮结束后再试，连续卡住就把报错交给维护者。
- 「暂存失败：」：请维护者检查交换目录的文件权限和 Git 状态，保留文件后再处理。
- 「提交失败：」：请维护者查看后附报错，检查仓库状态与权限，不删除文件来绕过。
- 「拉取失败：」：核对网络、远端地址和本机访问授权，恢复后重试。
- 「和远端合并失败：」：停止重复尝试，请维护者核对两端内容并保留数据；代码会尝试中止此次合并。
- 「推送失败：」：核对仓库写权限、认证和网络，保留已有本地提交后重试，不强制推送。
- 「不允许的 git 命令」：这是后台命令校验拒绝，请维护者查调用原因，不绕过校验。

其他失败可能直接返回 Git 或文件系统的具体报错，而不是固定中文原因；记录错误信息交给维护者，转述前去掉可能出现的凭证。状态未接通时，也不要自行修改插件或 Codex 配置来绕开缺失的界面。
