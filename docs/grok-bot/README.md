# Grok Bot 与 X 工作台搭建说明

用一个独立的 GitHub 私有仓库交换文件：Grok Bot 读取 X、准备回复并通知你；插件读文件、整理候选稿；所有内容都由你亲自打开预填链接并在 X 发送。插件不会自己读取 X，也不会代发、点赞、回复、转发或关注。

| 指令 | 做什么 | 建议频率 | 读取 | 写入 |
| --- | --- | --- | --- | --- |
| [01 读取选题素材](01-read-posts.md) | 取最近 24 小时帖子和最新互动数 | 每 2 小时 | voice/watchlist.json 的 topic、X | posts/ |
| [02 趁热准备回复](02-hot-replies.md) | 为 30 分钟内新帖准备两条回复并通知 | 白天每 10–15 分钟，以 Bot 允许的最短间隔为准 | voice/watchlist.json 的 engage、voice/SKILL.md、replies/、对话、X | replies/ |
| [03 送达候选稿并收集答复](03-deliver-and-collect.md) | 送稿，把你的明确答复交回插件 | 每 30 分钟 | drafts/、decisions/、对话 | decisions/ |
| [04 读取自己已发内容](04-read-mine.md) | 取最近 48 小时已发内容及当前粉丝数 | 每小时 | 对话中指定的本人账号、X | mine/ |

这些频率是创建 Bot 定时任务时的建议，插件不替 Bot 调度。文件格式见 [字段与示例](file-formats.md)。这些文档长期作为使用说明保留，文件格式改变时应一起更新；不要在这个文档目录存放账号资料、口令或运行数据。

## 1. 在 GitHub 新建私有仓库

打开 `https://github.com/new`，填写一个仓库名（例如 x-desk-exchange），选择 **Private**，勾选添加 README，然后创建仓库。README 是仓库的说明文件，勾选后才会有初始提交和默认分支。

成功时，仓库标题附近显示 Private，文件列表有 README.md，分支为 main。以下命令按 main 编写；如果默认分支不是 main，先核对实际分支名，并将下面的 main 换成它，别直接照抄。打开仓库的 Code 菜单，复制你有访问权限的仓库地址，后面用它替换 `<仓库地址>`；不要把口令或访问凭证放进地址、聊天或文件。

## 2. 把交换文件夹接到这个仓库

“工作副本”就是电脑上与远端仓库对应的本地文件夹。先打开 X 工作台设置，查看“交换文件夹位置”下的“当前使用”；默认是 `~/.dsh/x-desk/exchange/`，其中 `~` 表示你的用户目录。后台启动后会创建所需的六个子文件夹。

**交换文件夹不能放在插件代码文件夹里面。** 代码会明确拒绝：“交换文件夹在代码仓库里面，不能同步”。它也必须是一个独立仓库的根目录，不能只是别的仓库的子目录。原版插件数据目录也不能用。

打开电脑的终端，一次复制下面一个命令块，替换尖括号及其中的文字后回车；路径保留引号。这里只操作交换文件夹，绝不要在插件源码文件夹执行。任何一步报错就停下，对照文末故障说明处理，不用删除、重置或强制覆盖来继续。

先打开一次工作台，等它创建交换文件夹（设置里能看到路径）。再进入设置显示的交换文件夹，成功时终端没有“目录不存在”的报错：

```bash
cd "<你的交换文件夹>"
```

检查这个文件夹是否已有仓库，成功时输出仓库根目录；出现“不是 git 仓库”的错误才说明可以做下一条初始化：

```bash
git rev-parse --show-toplevel
```

**仅在尚未成为仓库时**，初始化名为 main 的本地分支，成功时会提示已初始化仓库；如果上一条输出的是其他父目录，先停下，不在里面继续建嵌套仓库：

```bash
git init -b main
```

将 origin（远端的本地简称）指向你刚建的私有仓库，成功时通常没有输出：

```bash
git remote add origin <仓库地址>
```

如果提示 origin 已存在，不重复添加、更不要改掉已有地址；运行 `git remote -v`，确认地址就是这个私有交换仓库后才继续。这个仓库应仅用于交换文件，不能夹带其他项目或已经暂存的无关文件。

### 让 GitHub 访问不再询问密码

推荐先安装 GitHub CLI（GitHub 的命令行登录工具），然后运行：

```bash
gh auth login
```

选择 GitHub.com、HTTPS 和 “Login with a web browser”，按提示在浏览器完成登录，然后运行：

```bash
gh auth setup-git
```

带口令的 SSH 密钥只有先加载进 ssh-agent（本机代管已解锁密钥的程序）才能用于同步。插件从不询问或保存密码。

取回远端分支信息和初始 README 提交。检查标准是下面的命令不询问密码即可完成，随后能看到 origin/main：

```bash
git -C <你的交换文件夹> fetch origin
```

把远端的初始提交接到本地 main，成功时交换文件夹出现 README.md；这一步让刚初始化、还没有提交的 main 真正存在，避免直接设置上游失败：

```bash
git merge --ff-only origin/main
```

这条命令也适用于能直接向前更新的已有 main 分支；如果本地已有不同历史、同名 README 或其他文件冲突，命令可能拒绝，此时保留现有文件，按下文“同步卡住怎么办”迁往新文件夹。

让 main 记住以后与 origin/main 对应，成功时提示分支 main 已跟踪 origin/main：

```bash
git branch --set-upstream-to=origin/main main
```

这里没有要求你提交或推送任何源码。GitHub 的登录访问需要在本机事先可用；插件同步时不会弹出终端密码提示。若本机缺少 Git，先安装 Git；访问认证按上面的登录步骤完成后再继续。

## 3. 在 Grok Bot 连接这一个 GitHub 仓库

在你所用 Grok Bot 的连接或集成入口选择 GitHub，进入授权页后只勾选上面这个私有仓库，允许它读取仓库并新增任务输出文件；不要授权全部仓库。成功标准是 Bot 能确认该仓库并读取其中的 README.md。

仓库里没有 Grok Bot 的界面或连接器实现，本项目不能核实其菜单名称及账号支持情况。如果你找不到 GitHub 连接入口、不能将授权限定到这一个仓库，或 Bot 无法提交推送，先停止，在该产品的帮助或支持入口核实连接与仓库授权能力；不要把口令粘进指令当替代办法。

## 4. 填账号名并打开同步

在工作台打开“设置”，找到“我的账号名”，填入自己的 X 账号名（不带 @，只含英文字母、数字、下划线，最多 15 个字符），点击保存。再次打开设置能看到所填账号名，才算这部分成功。把同一个账号名明确告诉 Bot 的第 04 个任务；插件不会把此设置导出到仓库。

同步默认关闭，后台默认间隔为 120 秒。开启同步意味着授权插件对这个独立交换仓库提交并推送，并从已配置的远端取回内容；它不代表授权发送 X 帖子。同步会暂存六个交换子目录里的变动、提交、取回远端、合并后再推送；它还可能提交仓库里本就已暂存的改动，因此这里应当只有交换用途的数据。

在设置的“与 Grok Bot 同步”分组中，勾选“打开同步”，将“同步间隔（秒）”保留为 120，点击保存。再次打开设置，按“现在同步一次”；状态行会显示连接情况及故障建议。看到“同步好了”的提示，且状态行显示“已连接”和上次同步时间，才表示这一轮成功；如有错误，按文末说明处理。“已连接”但“还没同步过”只表示仓库配置检查通过，不证明 GitHub 认证或推送成功。仍需第 6 步的文件往返验证。

## 5. 创建四个定时任务

完成一次同步后，在 Grok Bot 的定时任务入口分别新建四个任务，名称与上表对应。逐一打开上表链接，复制“复制下面整段”下整个代码块的内容到任务指令栏，包括其中的 JSON 示例；按表设置频率。保存定时任务前，把第 02 份里的 `<白天时段，例如 09:00–22:00>`、`<时区，例如 Asia/Shanghai>` 和第 04 份里的 `<你的 X 账号名>` 换成你的实际值。

每个任务都要指定第 1 步的同一个私有交换仓库。第 02 个任务另确认你的白天时段和按哪一个时区计算“每天”；第 04 个任务另说明自己的账号名；第 02、03 个任务需要能读取既有通知和答复记录，否则应先追问，不能假装没有历史。

成功时可看到四个已保存任务、各自的运行频率及完整指令。Bot 的可用调度间隔和对话记录能力由你使用的产品决定，本仓库不保证它提供这些入口；缺少能力就停下，通过该产品的帮助或支持入口核实。保存任务不等于跑通过，真实读写留到下一步验收。

## 6. 按联调清单验证

逐项核对：Bot 新文件到达插件、候选稿送达对话、明确答复返回插件、本人实际发出内容被采集并进入复盘。只有文件往返和处理结果都确认，才算整条流程接通；创建仓库、保存任务或状态检查通过都不能替代这个验收。

## 出了问题怎么办

以下是同步状态或执行结果中的原因原文；带冒号的条目是固定前缀，后面会跟 Git 的具体报错。含“…”的条目会显示具体文件或文件夹名。

- 「交换文件夹还不存在」：检查设置显示的路径，先打开工作台让它创建交换文件夹。
- 「交换文件夹在代码仓库里面，不能同步」：按下文恢复步骤，在代码仓库外使用新的独立交换文件夹。
- 「没有安装 git」：安装 Git，重新打开工作台，再检查同步状态。
- 「交换文件夹还不是一个 git 仓库」：按第 2 步初始化并接上新建的私有仓库。
- 「交换文件夹不是一个独立的 git 仓库」：必须使用独立克隆的仓库根目录；不能用父仓库的子目录、共享 Git 数据的 worktree（额外工作副本）或指向外部 Git 数据的 gitfile，按下文恢复步骤新建克隆。
- 「这个仓库没有配置远端」：按第 2 步核对 origin 指向你自己的私有交换仓库。
- 「当前分支没有上游分支」：先确认本地 main 已接上远端初始提交，再设置 origin/main 为上游。
- 「上一轮同步还没结束」：等待上一轮结束后再试，持续卡住则关闭同步、保存并重新打开工作台。
- 「暂存失败：」：查看后附报错，检查交换文件夹是否可写，并用下文 status 命令查看状态。
- 「提交失败：」：查看后附报错，检查仓库状态与权限，保留已有文件后处理。
- 「拉取失败：」：核对网络、远端地址和第 2 步的 GitHub 登录，恢复后重试。
- 「和远端合并失败：」：插件会尝试中止此次合并；反复出现时按下文恢复步骤处理。
- 「推送失败：」：刚好撞上 Bot 推送时等下一轮；持续失败则核对写权限、认证和网络，不强制推送。
- 「远端改动了不该改的文件（…），已停止同步」：检查所列文件（如 .gitignore、.gitattributes、.seen-*.json），让 Bot 只新增四种输入目录中的记录，再按下文恢复步骤处理。
- 「交换文件夹里的 … 不是普通文件夹，已停止同步，请检查仓库」：关闭同步并保存，检查所列位置是否为符号链接或文件；保留备份，在新克隆中放入真实的普通文件夹，未确认前不要重新开启同步。
- 「不允许的 git 命令」：保留报错及触发步骤，连同操作步骤报告给插件开发者，不绕过命令校验。

其他失败可能直接返回 Git 或文件系统的具体报错；记录错误信息，转述前去掉可能出现的凭证。

## 同步卡住怎么办

Grok Bot 刚推送后只出现一次「推送失败：…」，通常是两边恰好同时推送，下一轮一般会恢复。反复出现「和远端合并失败：…」或「远端改动了不该改的文件…」，说明两边内容已经分叉，需要保留数据后重新接上仓库。

可先用下面两个只读命令查看未提交文件和最近五次提交；替换路径，含空格时给路径加引号：

```bash
git -C <你的交换文件夹> status
```

```bash
git -C <你的交换文件夹> log --oneline -5
```

安全恢复步骤如下，不重置、不强制覆盖远端、不删除任何原文件：

1. 在设置中取消勾选“打开同步”并保存，等正在运行的一轮结束。
2. 把整个交换文件夹复制到别处作为备份，保留原文件夹。
3. 在代码仓库外准备一个新的空文件夹，把私有仓库克隆进去；将地址和文件夹替换为实际值，含空格时加引号：

```bash
git clone <仓库地址> <新文件夹>
```

4. 将备份里的六个子文件夹 `posts decisions drafts voice replies mine` 复制到新文件夹，合并文件夹内容。遇到同名文件提示时，`drafts`、`voice` 保留备份版本，另外四个保留新文件夹版本；不要整目录替换，以免丢掉只在一边存在的文件。备份和原文件夹都继续保留。
5. 在设置里把“交换文件夹位置”改成新文件夹的完整路径，保存。
6. 勾选“打开同步”并保存，再按“现在同步一次”，查看结果并按第 6 步核对文件往返。
