# 多账号工作区与快手支持

此功能面向同时维护多个自媒体账号的创作者：先选择账号，再在该账号内管理内容、排期、复盘、资料和风格。多个机器人也可以通过明确的账号 ID 并行操作同一个工作台。

## 版本与兼容

此文档对应源码准备版本 `2.7.0-accounts.5`；运行中的安装需另行更新。每次导出都新建唯一目录，既有文件与用户修改保留。内容版本随作品归属，恢复不改变当前账号或发布状态，详见[版本与导出](automation.md#persistent-content-versions-and-exports)。

首期内容评估保持「账号总菜单 → 账号 → 内容/排期/复盘/账号/风格」结构。内容页版本历史旁可选择保存版本与体裁，主动评估、生成单独预测预览并阅读后锁定；实际发布由本人声明，排期不等于已发布。复盘页即使无图表数据也显示账号队列，区分未到期、到期可复盘、等待可靠数据与迟到观测。完整预览未加载、内容编辑未保存或预览已失效时不能锁定。编辑再撤销不能恢复旧预览资格。

评估/预测/复盘各调用一次当前订阅或默认连接模型，不额外要求 API Key；查看/锁定/发布登记不调用模型。预设为未校准标准，维度 0–5、综合分 0–100，信心为模型自评而非实测准确率。历史数据已知作品只能作历史评估。基线取同账号/平台/体裁/窗口、每篇到期后六小时内最早观测，再选最近 20 篇；选中数量与全部可用历史分别披露。少于三篇或中位数为零时仅定性；概率并列不虚构唯一命中。实际采集时间、迟到累计性质、未知数据和发布时稿件不匹配均保留。

记录不可改写，普通撤销、删除或重新归属不会删除历史；归档留在原账号与「全部」，不会跑到新账号。网络中断后保留原核对编号和输入，只读核对，不自动重放。详见[接口、CLI 与恢复说明](automation.md#saved-version-review-prediction-and-timed-retrospective)。`.5` 尚未发布 npm，也未更新实际安装；原已核验运行版本仍为 `.3`，市场索引保持 `2.7.0`。人群画像、对标、选题和公式重校属于后续增量。方法参考 [XBuilderLAB/cheat-on-content](https://github.com/XBuilderLAB/cheat-on-content)（[MIT 许可](https://github.com/XBuilderLAB/cheat-on-content/blob/d88d004abcabfe6656a007b8fb4e7ed4ea7a4c89/LICENSE)，提交 [d88d004abcabfe6656a007b8fb4e7ed4ea7a4c89](https://github.com/XBuilderLAB/cheat-on-content/commit/d88d004abcabfe6656a007b8fb4e7ed4ea7a4c89)）。

`2.7.0-accounts.5` 已整合上游 `2.7.0`：保留脚本/文章体裁、风格原文参考与逻辑/讲述/衔接字段、单次生图选择、百炼/万相协议，以及 better-sidebar 入口，同时保留多账号工作区、快手与 CLI/MCP，并新增本机图片/视频导入。

自定义版本用于本功能分支；插件市场 `index.json` 仍指向已公开发布的上游 `2.7.0`，不会把未发布的自定义包标成 npm 可安装版本。

## 使用流程

1. 打开「自媒体工作台」，进入账号总菜单。
2. 创建或选择账号。列表支持名称/ID 搜索、平台与分组筛选、归档恢复、每页 50 个账号，以及每次最多 100 行的 CSV 添加。失败行保留，便于修正后继续。
3. 进入账号后，使用「灵感、内容、排期、复盘、账号、风格」六个子页面。「账号」仅显示和编辑当前档案；「账号列表」返回总菜单。
4. 每个账号分别设置定位、受众、默认风格和脚本/文章体裁。模型继续使用工作台已有连接，风格卡库共享。
5. 在内容表格中勾选稿件，批量分配给账号或移回「未归属」，每次最多 100 条。跨平台分配需要明确选择同步更新平台；生成中禁止改归属。

「全部账号」和「未归属」作为总菜单中的独立入口保留。机器人在界面外修改数据后，可点击账号列表的「刷新」。

账号 CSV 列顺序：`平台,账号名称,分组,主页链接,账号定位,目标受众,备注`。

```csv
平台,账号名称,分组,主页链接,账号定位,目标受众,备注
快手,历史知识号,知识矩阵,,讲解历史故事,历史爱好者,
抖音,科技知识号,知识矩阵,,解释科技概念,入门读者,
```

账号档案用于创作数据管理。平台登录和自动发布需要各平台的单独接入；日历排期只修改工作台记录。

## 账号头像

添加或编辑账号时，可选择本地 JPEG、PNG 或 WebP（最多 5 MiB，界面显示为 5 MB）。浏览器会居中裁剪并压缩成 256 × 256 WebP，先显示预览，点击「保存账号」时才通过现有上传接口保存；取消选择后的表单不会上传或创建内容卡片。也可填写可选的 HTTP(S) 头像链接。账号列表、档案页及当前工作区标题显示圆形头像；未设置或加载失败时显示稳定颜色的名称缩写。「全部账号」和「未归属」保留文字标识。

`avatar` 与账号其他字段一起通过 `applyOps` 保存。合法值为最多 4000 字符的 HTTP(S) URL，或工作台已有的 `media-desk/files/文件名.jpg` / `media-desk/assets/文件名.png` 等图片相对路径（JPEG、PNG、WebP、GIF）；本地任意文件路径、内联 base64、SVG、视频和路径穿越均被拒绝。CLI/MCP 的 `add_account`、`update_account` 支持此字段，`list_accounts`、`get_account` 返回头像引用；自动化不接收或上传图片字节。

「移除头像」或设置 `avatar:null`（空字符串也可）清除引用。替换和移除不删除已上传文件，便于常规「撤销」恢复；上传成功但保存失败时，同一表单重试复用这次上传。头像操作无需 API Key、平台登录或模型调用，旧档案与已有头像保留。

## 旧数据与账号边界

- 迁移是增量且可重复执行的，已有 ID、正文、成稿和指标保留。缺少归属的内容保持「未归属」，不会仅凭平台或昵称自动分配。
- 同平台、同名账号使用独立 ID。账号选择仅属于当前界面；服务端没有会被其他机器人改写的全局当前账号。
- 内容、关联指标、助手历史、模型上下文和模型返回的修改/生成动作按明确范围处理。聚焦稿件时可从稿件推导账号，显式账号不匹配会在调用模型前拒绝。
- 归档保留数据。删除账号会把内容、指标、规则和历史移回未归属；清空示例同样保留用户后来添加的内容。
- 批量分配先验证全部目标，关联指标跟随内容，分支不被隐式搬动。生成中的归属锁也适用于撤销，生成后续写入再次校验原账号。
- 不同账号的同名稿件导出到各自的账号目录；每次导出新建目录，改归属后不会覆盖原账号的导出文件。既有保存位置在原归属下继续保留。

## 快手

平台目录统一用于界面、助手提示词、自然语言排期、CSV、结构化操作和复盘查询，包含快手及其他既有平台。

- 复盘页可筛选「快手」，手动数据录入支持快手，CSV 也接受 `Kuaishou`、`Kwai`。
- 结构化 CLI/MCP 请求使用规范值 `快手`。`media_desk_status.supportedPlatforms` 返回可用平台，查询前可先发现能力。
- 账号范围先应用，再应用平台筛选。独立指标参与总量；缺少平台字段的旧稿件，只要有明确的快手关联指标，也参与快手排行。
- 自然语言排期支持「快手」「Kuaishou」「Kwai」，标题中的 `Project X` 不会抢占明确的平台名称。

快手数据支持手动、CSV 和 API 导入。本次没有新增 Monid 快手抓取端点，自动抓取维持现有接入范围。

## 体裁、风格和图片

成稿工作区的体裁选择只修改这条稿件所属账号的偏好。账号的 `draftFormat` 可为 `script`、`article`，或 `null`（继承旧版全局偏好）；未归属内容继续使用全局偏好。新增字段不会改写旧稿的正文或已有体裁。每次开始成稿时固定体裁，期间再改偏好只影响下一次生成。 撤销此前的导入会保留后来新生成的完整成稿，生成中与完成后都适用；同一次成稿内的普通编辑、账号偏好和无关修改仍可正常撤销。

生图开关可按单次生成覆盖设置中的默认值。关闭生图仍会写正文和分镜文案，并保留画面规划；之后可单张补画。重复并发启动同一稿件只接受一个任务，跨账号请求在模型或生图调用前拒绝。

提炼风格时保留有长度上限的原文，以及逻辑、讲述和衔接字段；原文仅用于正文提示词，精简 CLI/MCP 风格读取不返回原文。

## CLI 与 MCP

自动化适配层与界面共用 Store、模型连接和生成器，提供 20 个精简工具；无需再开一个 Harness 服务。常规写稿/改稿调用工作台模型；`write-draft` 用于直接导入现成稿件。

`media-desk import '/本机路径/图片.png' --input '{"accountId":"ACCOUNT_ID"}'` 或 MCP `media_desk_import_file` 将一个本机图片/视频加入该账号灵感，并继承平台；省略账号或传 null 则加入未归属。账号在文件读取前和串行保存时都会校验，期间被删除则清理此次副本并失败，不会悄悄转为未归属。MCP 路径必须是工作台电脑上的绝对路径，云端文件不会自动传输。JPEG/PNG/WebP/GIF 限 25,000,000 字节、4000 万像素、单边 16384；MP4/MOV/WebM 限 250,000,000 字节。复制保留原始字节与源文件，不转码、不调用模型。仅返回元数据、SHA-256 和媒体引用，可通过 `get_item.fields:["media"]` 查看。`--input-file` 仍只读取 JSON。相同 requestId 和参数最多复制一次；不确定结果通过请求状态与 `list_items.query` 搜索 `importRequestId` 核验，不能换新 ID 重试。详见[本机媒体导入](automation.md#local-image-and-video-import)。

同一工具设置 `destination:"avatar"` 可直接导入指定账号头像，仅接受图片，必须提供具体 accountId，不接受 title/body/tags，不新建灵感，也不裁剪或压缩。`get_account`/`list_accounts` 仅在当前头像与导入记录相同时返回 `avatarImportRequestId`；之后手动替换或删除头像会隐藏旧标记，撤销可恢复对应引用，导入文件保留。结果不确定时核对该账号当前头像与请求标记。内部恢复标记不能通过 apply_ops 伪造。

```sh
media-desk doctor
media-desk accounts list --input '{"limit":20}'
media-desk accounts add '历史知识号' --input '{"platform":"快手","group":"知识矩阵"}'
media-desk items list --input '{"accountId":"ACCOUNT_ID","limit":10}'
media-desk call media_desk_get_insights --input '{"accountId":"ACCOUNT_ID","platform":"快手"}'
media-desk produce ITEM_ID --input '{"accountId":"ACCOUNT_ID","withImages":false}'
media-desk write-draft ITEM_ID --input '{"accountId":"ACCOUNT_ID","format":"article","article":"已写好的文章"}'
```

`accountId` 省略时保持全部账号的兼容行为，`null` 表示未归属，字符串表示确切账号。写操作使用持久化的 `requestId` 去重；遇到结果未确认，先查请求状态，不换 ID 盲目重试。只读模式会移除并拒绝写工具。

本机桥接使用私有 Unix socket，目前支持 macOS/Linux；Windows 上不启动该自动化桥，普通工作台仍可继续使用。可选 HTTP MCP 需要显式启动和独立凭据，默认仅监听本机；包本身不会部署公网入口。

安装与全部工具参数见 [automation.md](automation.md)，客户端配置见 [media-desk.mcp.json](media-desk.mcp.json)，Grok 本机执行建议见 [GROK_BOT.md](GROK_BOT.md)。示例中的可执行文件路径需按自己的安装调整。

## 验证

运行 `npm test` 和 `npm run build`。自动测试覆盖账户层级、界面范围、异步旧响应、归属/撤销/生成锁、导出并发与同名文件隔离；也覆盖 2.7.0 体裁、风格参考、图片开关、后续补画、并发启动和百炼/万相协议。

接口测试使用临时 Store、模拟文字/图片模型和 Monid，以及官方 MCP 客户端，不消耗真实模型或抓取额度。CLI 与 MCP 使用同一严格参数目录，共 20 个工具。媒体导入测试使用本机临时文件，核验原始字节、拒绝非法输入、重复请求、账号失效和不确定保存。实际桌面安装、各操作系统和机器人连接仍应在目标环境核验；升级前备份现有数据与设置，升级后核对记录数量、正文和账号归属。
